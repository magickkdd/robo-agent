**三处必须记下来的错，前两处比结论更要紧。**

**一、停止规则报了一次"界内通过"，而它什么都没量到。**第一版按"我传给 `run_group` 的那个
目录"去找账本，而 `run_group` 会在它下面建一个带时间戳的子目录。于是 glob 找到一棵空树、
求和 0、打印 `spent 0, completed within bound`——**一次对着空检查的干净通过**。这批其实确实
在界内（216 < 411），所以**界是靠投影的运气守住的，不是靠检查**。现在按**每批自报的 run root**
去读，而且**读到 0 一律拒绝继续**，而不是当成好消息报出去。零读数是检查的失败，不是预算的胜利。
（与 P6-a 同类：读数指错地方。区别是**那个报成功**。）

**二、`M2.followed_round_share` 读出 0/15，而那是编出来的负数。**那一行读
`episode_summary.policy.trace`，由 `MemoryPolicy` 自己逐轮写下；模型席上决策者是模型规划器、
`policy=None`，**没有 policy 跑过、那条 trace 没人写**。实测：rule 席 **16/16** 集摘要带
`policy` 块（100 条 trace，14 条 `memory_followed` true），模型席 **0/14**。0 读起来像**证据**，
缺席的仪器不像——这是本项目最危险的形状。已改为**结构性 not-measured**，并写明该读哪一行。
而且不止两行：**五行**读同一条 trace（`memory_followed` / `memory_declined` / `memory_order`），
把 M3/M4 当成 0 发出去是同一个编造的负数换了个名字。被抑制的格子**保留它本来在数什么**
（`suppressed_as`），否则读者分不清"真的是 0"和"这个席没资格数"。

**三、我把 v0.2 一条有意做的决定反转了，然后才发现。**v0.2 的契约写着"账本说跑了但盘上没有
那一集，**必须拒绝**，不能拿活下来的配对去算一个率"。我的 `pair_arm_ran` 直接把行当成了运行，
把那条拒绝变成了"absent"——等于用悄悄缩小分母换掉了它防的东西。两种顾虑都成立，而**状态是
可以分辨的**，所以现在是三态：**跑了**（有 episode 目录）／**失败且有记录**（根目录在、没有
episode、目标账本写了错——就是 429 那一批）／**不明**（根路径压根不存在，交给 reader，生产里
它本来就会带路径名拒绝）。第四种不是状态而是**拒绝**：根目录在、没有 episode、**且什么都没记**
——那是账本损坏，不是失败的运行。v0.2 的拒绝原样保留，只收窄到它本来针对的**静默**情形。
